# SCAPI backlog по критичности

Документ фиксирует технические задачи, упорядоченные по степени критичности. Используем его как чек‑лист перед началом предметной логики.

## Критично (блокеры запуска)

- **Go toolchain** — в `src/go.mod` указана версия `go 1.24.9`, которой ещё нет в релизах. Любой `go build`/`go test` завершается ошибкой. Нужно зафиксировать поддерживаемую версию (например, 1.22/1.23) и обновить описания в README/CI.
- **Проверка JWT** — middleware `cmd/scapi/internal/server/middleware/claim.go` через `utils.CreateContextWithClaim` вызывает `jwt.Parser.ParseUnverified`, полностью игнорируя подпись и `exp/iss/aud`. Требуется полноценная валидация токена (JWK/HS256 ключ, проверки claim’ов) и понятные HTTP‑ответы при сбое.
- **Грациозное выключение** — `HostedService` хранит `server.Server` по значению и никогда не присваивает туда инстанс из `server.NewServer`, из‑за чего `Stop` не останавливает `http.Server`. Нужно хранить ссылку на живой сервер и корректно завершать ListenAndServe/active connections.
- **Middleware Timeout** — текущая реализация запускает обработчик в отдельной горутине и при таймауте пишет 504 поверх того же `ResponseWriter`, что приводит к гонкам и двойной записи. Следует либо использовать `http.TimeoutHandler`, либо буферизовать ответ и атомарно прерывать выполнение.

## Высокий приоритет

- **Жёсткая зависимость от `Origin`** — `TenantGuard` требует, чтобы `tenant.Host` совпадал с `routeInfo.Domain`, где домен берётся исключительно из заголовка `Origin`. Любой backend‑клиент без этого заголовка получает 403. Нужен fallback (например, `Host`) и конфигурируемые алиасы.
- **Ключ для survey‑токенов** — `tenantsvc.NewService` безусловно вызывает `tokencoder.ParseKey` и `tokencoder.New`. Без `tenants.key` сервер не стартует. Нужно сделать ключ обязательной конфигурацией или позволить отключать код‑путь.
- **AWS Parameter Store** — `internal/config` поддерживает схему `ssm://`, но функция `loadParameterStore` всегда возвращает `errors.New("parameterStore is not implemented yet")`, ломая запуск при указании такого сорса. Надо либо реализовать до конца, либо временно задокументировать отсутствие поддержки.

## Средний приоритет

- **Документация** — `Docs/architecture-sc-api.md` описывает старый стек MSSQL и пакет `internal/sqlserver`, хотя код уже на PostgreSQL (`internal/postgres`). Нужно синхронизировать описание архитектуры, чтобы ускорить онбординг (частично выполнено в текущем PR — следить за актуальностью).
- **Retry‑логика** — `internal/postgres/retry.go` всегда возвращает `false` из `canRetry`, поэтому повторов нет, несмотря на комментарии. Следует определить перечень транзиентных ошибок (SQLSTATE, сетевые) и реализовать экспоненциальный backoff.
- **Покрытие тестами** — существуют только smoke‑тесты (`bootstrap`, `lambda`). После стабилизации критичных моментов нужны unit‑тесты для middleware и сервисов, а также интеграционные тесты поверх PostgreSQL контейнера.
