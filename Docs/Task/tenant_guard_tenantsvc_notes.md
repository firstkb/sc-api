# Замечания по tenantsvc и tenant_guard

1. **Потеря доменов при выборке по tenant_id**
   - `repository.GetByID` обращается к `v_tenant_by_host`, но использует `QueryRow`, поэтому возвращает только первую запись и один домен. Для многодоменных tenants Origin-проверка будет падать даже при корректном Origin, т.к. остальные домены не считываются.

2. **Сравнение Origin без нормализации**
   - В `ServiceTenantProvider.Validate` сравнивается `tenant.Host` и `domain` строковым равенством. Домены в view всегда нижним регистром, а заголовок Origin может содержать регистр/порт. Нужна нормализация (lowercase, отрез порт) и поддержка нескольких хостов.

3. **TierPublicTenant больше не поддерживается**
   - Новый `TenantGuard` вызывает `Validate` только для TierSecure, но сам `Validate` жёстко требует Claim. Публичные маршруты без JWT теперь не могут резолвить `tenant_id` и проверять Origin — потеря прежнего функционала.

4. **Нет кэша и интерфейса**
   - Service теперь лишь thin-wrapper над репозиторием, каждый запрос идёт в master БД. Нет TTL-кэша, запроса через интерфейс и удобного мокирования — возрастает нагрузка и усложняется тестирование.

5. **Неполная валидация статуса/изолированности**
   - Несмотря на то, что `v_tenant_by_host` возвращает `status`, `isolation`, `plan`, логика пока только проверяет `status == "active"` и не делает ничего с остальными полями. Потенциал view не раскрыт.
